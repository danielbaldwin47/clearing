# Acceptance contract

Started: 2026-09-19 22:46:22 UTC.
Hard freeze: 2026-09-20 00:46:22 UTC (20:46:22 America/New_York).

The target is a Linux terminal application showing a scanned directory as a
sunburst or treemap, allowing drill-in/back and confirmed deletion.

The independently prepared visual comparisons use the four saved DaisyDisk
stills and diskonaut run against the same directory as the candidate. The
referee owns reference selection, state alignment, crops, normalization,
randomized order, private answer keys, and verdict recording. The builder never
prepares its own examination. Critics start with fresh context and only the
anonymous pair. They choose one entry, cite concrete evidence in both, and name
the single largest cause of the loser's defeat.

Calibration must prefer the reference to a rough draft. Shared
colour, type, and size encoding are judged before separate overview, navigation,
and deletion pieces. The user amended the rule: a win requires one fresh critic choosing the
unchanged candidate. A first-round win requires an audit
before it can count. A later source change invalidates affected wins. The final
whole-app comparison begins only after every piece has won. The progress page
and machine-readable state preserve every verdict and its evidence.

Scan timing comes from an independent script, comparing the same directory
with gdu and the release build. Cold-cache claims require actual cache eviction,
not merely a new process or a file cache hint. Warm and cold results are separate.
Correctness and failure cases are checked independently of visual preference.

At the deadline, work freezes. Every piece without one valid win is lost.
No time limit, passing diagnostic, or partial implementation counts as a win.
