# Referee protocol

The referee prepares every comparison and is never a builder or critic. Builders do not select screenshots, order, framing, or answer keys. Critics are fresh agents with only a random blind-packet path. A packet contains A.png, B.png, and an identity-free brief. Semantic file labels, size values, paths, and actions remain visible; app names, logos, operating-system furniture, outer window chrome, and terminal borders are removed. Both entries use one canvas and the same state category. Images are never stretched. The reference is fitted to the canvas using its own background colour.

References were downloaded once to references/ and are verified by SHA256SUMS. Future comparisons read those copies. Intro-ss1 and shots-ss show drilled folders with a delete collection; intro-ss2 shows root overview; intro-ss3 is a volume picker and is retained as visual-language evidence, not misrepresented as a delete confirmation. The live second bar supplies matched drill-in and delete-confirmation states.

The referee encrypts each answer key outside this repository. The encryption key exists only in the referee's private execution context. A/B order is randomized independently for each fresh critic. Answer keys are disclosed only after each critic commits its verdict.

Calibration compares an intentionally rough builder draft with the saved visual bar. It must favour the bar with one fresh critic before product rounds count. Shared colour, typography and size encoding are decided before overview, navigation and confirmation. A piece requires one fresh critic choosing it. A first-round win triggers a validity investigation and cannot count until the referee documents why the trial was discriminating. Editing any source on which a win depends resets that win. The whole interface then faces the whole applicable bar.

The critic question is: Which of these two would you rather use to find what is eating your disk and clear it? Each verdict must select exactly A or B, cite visible evidence in each, and give the single biggest reason the loser lost. Praise without comparative evidence does not constitute a verdict.

State is progress/state.json, written by atomic replacement. The live page polls it. Every verdict is recorded with the blind pair and revealed identity after judging. At 2026-09-20T00:46:22Z all work freezes. A piece without one valid fresh-critic win is lost; elapsed time cannot award a win.

## Rule history

The original four-hour limit and two-critic reversed-order requirement were replaced by the user: the operative limit is two hours, ending2026-09-20T00:46:22UTC, and one fresh critic win suffices. All other judging controls remain.
